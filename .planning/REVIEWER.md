# REVIEWER — инструкция проверяющему агенту

Читать первым в новой сессии Клода. Код здесь пишет локальная модель (Qwen через
OpenChamber), проверяющий — Клод. Человек не пишет код и не принимает решений по нему:
он запускает сессии модели и передаёт сообщения между агентами.

## С чего начать сессию

```
cd /c/neuroglyphs && git log --oneline -5 && git status --short && node tools/report.mjs
```

`report.mjs` печатает прогресс, коммиты с прошлой сверки, замечания аудита, состояние
тестов и страницы, пути к последним скриншотам. Дальше читать `.planning/ISSUES.md`
только вокруг текущей задачи, а не целиком.

## Что делать на каждой задаче

Три линии проверки, отчёту модели не верить ни в одной:

1. **Инструменты.** `npm test`, `node tools/browser-check.mjs`, `node tools/atlas-check.mjs`,
   `node tools/glyph-check.mjs`, `node tools/geometry-check.mjs` — что применимо. Смотреть, не ослаблены ли пороги:
   `git show HEAD -- test/ tools/`.
2. **Мутации.** Скопировать код в песочницу вне проекта, намеренно сломать и проверить,
   поймает ли тест. Это ловит бутафорские тесты — уже дважды срабатывало.
3. **Чтение кода.** Файлы по 50–150 строк, читаются целиком. Все четыре правки по ревью
   (`R1`–`R4` в ISSUES) найдены именно так, ни инструменты, ни тесты их не видели.

Найденное оформляется правкой `R` в `.planning/ISSUES.md` плюс строкой в таблице
«Правки по ревью» в `BACKLOG.md`. `next-task` выдаёт незакрытые `R` раньше задач `N`,
а `report.mjs` печатает их списком в начале отчёта. Статус `later` — принято, но
привязано к поздней демо-точке: такие не выдаются.

Найденное чинит **модель**, не Клод. Клод правит только задачи, инструменты, правила
и планы — то есть `.planning/`, `tools/`, `.clinerules`, `AGENTS.md`. Иначе в коде
появятся изменения, не прошедшие через воротa.

## Формат обмена

Модель присылает вывод `node tools/report.mjs` — блок `=== СООБЩЕНИЕ КЛОДУ ===`.
Ответ оформлять блоком, который человек вставит в сессию модели:

```
СООБЩЕНИЕ ДЛЯ МОДЕЛИ

<что проверено и чем, с числами>
<что принято, что нет>
<конкретная задача или «ничего не правь»>
<команда проверки и finish-task, затем STOP>
```

Первой строкой ответа человеку всегда писать, **в новую сессию или в текущую**. Правило:
задача закрыта — новая; правка того же файла и сессия меньше 40k входных токенов —
текущая; больше 40k — новая всегда. Размер сессий смотреть в базе:
`~/.local/share/opencode/opencode.db`, таблица `session`, поля `tokens_input/output`.

## Ловушки, которые уже стоили времени

- **Заглушка обходит воротa.** `N01` требовала ссылку на файл из `N02`, модель создала
  файл в одну строку, и признак «задача сделана» счёл `N02` закрытой. Признак усилен:
  файл засчитывается от 15 значимых строк и наличия `export`.
- **Тест зелёный, но бутафорский.** Сравнение двух экземпляров генератора внутри одного
  запуска не ловит потерю воспроизводимости. Лечится эталонными значениями в тесте.
- **Метрика не та.** Центровку глифов мерил по центру масс — получил ложный провал; мерить
  надо габаритный бокс. Перед тем как объявлять баг, проверять саму метрику.
- **Неканоничные коды сида.** `decodeSeed` маскировал старшие биты, поэтому один мир имел
  коды-синонимы, и пересохранение меняло мир. Плюс `rng` терял поле `exit` при `% 2^32`.
- **Отчёты по памяти.** Модель называет числа не из вывода команды: групп глифов, бит
  в сиде. Всегда сверять с диском.
- **`node --check` ничего не гарантирует.** `N09` закрылась модулем, который падал
  с `ReferenceError: THREE is not defined` на первом же вызове: импорта не было, а в
  ES-модуле `THREE` не глобальный. Синтаксис при этом безупречный, и `browser-check`
  файл не видел, потому что до `N11` его никто не импортирует. Вывод: у задачи, чья
  проверка — только `node --check`, надо либо звать модуль руками, либо заводить gate.
  Для геометрии поля такой gate теперь есть: `tools/geometry-check.mjs` подменяет three
  заглушкой и проверяет, что атрибуты действительно заполнены.
- **Выделено ≠ заполнено.** В той же `N09` атрибуты `glyph`, `size`, `offset` были
  созданы и остались нулями: каждая точка — глиф 0 размера 0, то есть чёрный экран
  на следующей задаче. Проверять не наличие атрибута, а разброс значений в нём.
- **Правка мимо конвейера.** Правки `R1`–`R4` жили только в тексте `ISSUES.md`, а
  `next-task` матчил `## N\d+` — то есть их не существовало для конвейера. Модель
  запустила `next-task`, получила следующую `N` и мои указания не выполнила. Любое
  указание проверяющего, которого нет в `BACKLOG.md`, будет обойдено: не «модель
  не послушалась», а инструмент её туда не пустил.
- **Всегда включённые воротa толкают модель за границы задачи.** `geometry-check`
  прогоняется в `finish-task` на любой задаче, поэтому сломанная геометрия не давала
  закрыть ничего: модель починила чужой файл, чтобы закрыть `R5`. Заводя новый gate,
  ставь правку, которая его снимает, первой по номеру — либо принимай, что следующая
  задача приедет с чужими файлами в диффе. `next-task` теперь зовёт предстартовую
  проверку после выбора задачи и пропускает её для правок `R`.
- **Отклонение от предписанного числа.** В `R7` был предписан разброс `size` 0.6..2.0,
  пришло 1..10. Инструмент такое не поймает: он проверяет «больше нуля» и разброс,
  а не конкретные границы. Числа, которые нельзя проверить без картинки, и не надо
  зашивать в gate — их место в примечании к задаче, где появится картинка.
- **Ворота, проходящие со второго раза, хуже отсутствующих.** `atlas-check` ждал
  атлас фиксированные 2500 мс, а страница тянет three с CDN: на тёплом кэше замер дал
  2.1–2.4 с, то есть запас был около сотни миллисекунд. Любая заминка — пустой канвас,
  «128 пустых клеток» и провал, уходящий при повторе. Так модель приучается просто
  запускать проверку снова. Теперь инструменты ждут готовности с жёстким сроком 25 с
  и печатают, сколько ждали. Пороги при этом не двигались: меняется терпение, не планка.
- **Код 200 не значит, что проверен этот проект.** Инструменты поднимали `server.mjs`
  с `stdio: 'ignore'` и не смотрели, поднялся ли он. Порт 5173 держал забытый
  `server.mjs` из прошлого прогона, и проверка в песочнице со сломанным `atlas.html`
  напечатала `ATLAS_OK` — читала файлы совсем другого каталога. Теперь `atlas-check`,
  `browser-check` и `check-server` сверяют отданный файл с тем, что на диске, и
  отказываются работать с чужим сервером. На этой машине на `0.0.0.0:5173` висит ещё
  и `server.js` другого проекта: как только чужой `server.mjs` умрёт, проверки начнут
  честно падать с требованием снять процесс — это правильное поведение, а не поломка.
- **Не та модель.** У OpenChamber есть свои бесплатные модели (`opencode/*`), они
  обрываются с нулевыми токенами. Проверять: `node C:\Users\onlin\cline-llm-proxy\agent-doctor.mjs`.
