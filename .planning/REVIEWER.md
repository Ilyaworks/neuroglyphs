# REVIEWER — инструкция проверяющему агенту

Читать первым в новой сессии Клода. Код здесь пишет локальная модель (Qwen через
OpenChamber), проверяющий — Клод. Человек не пишет код и не принимает решений по нему:
он запускает сессии модели и передаёт сообщения между агентами.

## С чего начать сессию

```
cd /c/neuroglyphs && git log --oneline -5 && git status --short && node tools/report.mjs
```

`report.mjs` печатает прогресс, коммиты с прошлой сверки, замечания аудита, состояние
тестов и страницы, пути к последним скриншотам. Дальше читать `.planning/ISSUES.md`
только вокруг текущей задачи, а не целиком.

## Что делать на каждой задаче

Три линии проверки, отчёту модели не верить ни в одной:

1. **Инструменты.** `npm test`, `node tools/browser-check.mjs`, `node tools/atlas-check.mjs`,
   `node tools/glyph-check.mjs` — что применимо. Смотреть, не ослаблены ли пороги:
   `git show HEAD -- test/ tools/`.
2. **Мутации.** Скопировать код в песочницу вне проекта, намеренно сломать и проверить,
   поймает ли тест. Это ловит бутафорские тесты — уже дважды срабатывало.
3. **Чтение кода.** Файлы по 50–150 строк, читаются целиком. Все четыре правки по ревью
   (`R1`–`R4` в ISSUES) найдены именно так, ни инструменты, ни тесты их не видели.

Найденное чинит **модель**, не Клод. Клод правит только задачи, инструменты, правила
и планы — то есть `.planning/`, `tools/`, `.clinerules`, `AGENTS.md`. Иначе в коде
появятся изменения, не прошедшие через воротa.

## Формат обмена

Модель присылает вывод `node tools/report.mjs` — блок `=== СООБЩЕНИЕ КЛОДУ ===`.
Ответ оформлять блоком, который человек вставит в сессию модели:

```
СООБЩЕНИЕ ДЛЯ МОДЕЛИ

<что проверено и чем, с числами>
<что принято, что нет>
<конкретная задача или «ничего не правь»>
<команда проверки и finish-task, затем STOP>
```

Первой строкой ответа человеку всегда писать, **в новую сессию или в текущую**. Правило:
задача закрыта — новая; правка того же файла и сессия меньше 40k входных токенов —
текущая; больше 40k — новая всегда. Размер сессий смотреть в базе:
`~/.local/share/opencode/opencode.db`, таблица `session`, поля `tokens_input/output`.

## Ловушки, которые уже стоили времени

- **Заглушка обходит воротa.** `N01` требовала ссылку на файл из `N02`, модель создала
  файл в одну строку, и признак «задача сделана» счёл `N02` закрытой. Признак усилен:
  файл засчитывается от 15 значимых строк и наличия `export`.
- **Тест зелёный, но бутафорский.** Сравнение двух экземпляров генератора внутри одного
  запуска не ловит потерю воспроизводимости. Лечится эталонными значениями в тесте.
- **Метрика не та.** Центровку глифов мерил по центру масс — получил ложный провал; мерить
  надо габаритный бокс. Перед тем как объявлять баг, проверять саму метрику.
- **Неканоничные коды сида.** `decodeSeed` маскировал старшие биты, поэтому один мир имел
  коды-синонимы, и пересохранение меняло мир. Плюс `rng` терял поле `exit` при `% 2^32`.
- **Отчёты по памяти.** Модель называет числа не из вывода команды: групп глифов, бит
  в сиде. Всегда сверять с диском.
- **Не та модель.** У OpenChamber есть свои бесплатные модели (`opencode/*`), они
  обрываются с нулевыми токенами. Проверять: `node C:\Users\onlin\cline-llm-proxy\agent-doctor.mjs`.
