# Промт для сессии модели

Вставлять в начало КАЖДОЙ новой сессии Квена целиком, ниже разделителя. Текст
постоянный — он не зависит от задачи, задачу выдаёт `next-task` уже внутри сессии.

Когда новая сессия, а когда та же:

- **новая** — после того как задача закрылась (`finish-task` прошёл), и после вашего
  отказа по приёмке глазами;
- **та же** — пока модель посреди задачи, а вы просто отвечаете ей: передали вердикт
  «принято», ответили на вопрос, уточнили формулировку.

---

Первым действием выполни: node tools/next-task.mjs

Дальше делай ровно то, что он напечатал, и ничего сверх этого.

Правила, которые важнее любой задачи:

1. Правь только файлы из списка задачи. Каталог tools/ не трогать никогда — если
   гейт кажется неправым, прогони его дважды на одном и том же выводе и напечатай
   ПРОВАЛ с числами, но инструмент не правь.
2. Не запускать git reset --hard, git checkout -- . и git stash. Ими уже трижды
   стёрло чужую незакоммиченную работу. Отменять только по именам файлов:
   git checkout HEAD -- <файл>.
3. Не править .planning/ISSUES.md и .planning/BACKLOG.md руками, не начинать
   следующую задачу, не менять пороги в тестах и инструментах.
4. Если finish-task откажет словами «нет вердикта приёмки глазами» — это НЕ поломка
   и не повод запускать снова. У задачи приёмка назначена глазами, и решает человек.
   Пересними картинку, напечатай человеку блок «ЧТО ПРОВЕРИТЬ ГЛАЗАМИ» целиком, как
   его выдал инструмент, и печатай STOP. Свои замеры вместо вердикта не подставляй:
   зелёные гейты не значат «сделано», когда приёмка назначена глазами.
5. Отчёт не сочинять. Числа брать из вывода команд, а не по памяти. Если проверка не
   прошла после трёх попыток — печатай ПРОВАЛ с номером задачи и остановись.

Закончив, напечатай STOP и короткий отчёт: какие файлы правил, что вывели проверки.
