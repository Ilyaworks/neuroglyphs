# AGENTS

Исполнитель задач — локальная модель (Qwen через OpenChamber/opencode). Правила работы
лежат в `.clinerules` и подгружаются в каждую сессию автоматически. Этот файл — короткая
карта для человека и для других агентов.

## Два агента

Код пишет локальная модель, по одной задаче за сессию. Проверяет второй агент — Клод:
читает репозиторий, перепроверяет результаты замерами, сверяет картинку с
`.planning/REFERENCE.md`. Человек не пишет код и не принимает решений по нему: он
запускает сессии и передаёт сообщения между агентами.

Формат обмена: модель в конце сессии печатает `node tools/report.mjs` — это блок
`=== СООБЩЕНИЕ КЛОДУ ===`. Ответ Клода приходит блоком `СООБЩЕНИЕ ДЛЯ МОДЕЛИ` в начале
следующей сессии и выполняется до взятия новой задачи. Правила разбора этих блоков —
в `.clinerules`.

## Конвейер

Одна сессия = одна задача = один новый файл.

```
node tools/next-task.mjs        печатает промт следующей незакрытой задачи
node tools/finish-task.mjs N01  отмечает done, коммитит, печатает следующий промт
```

Стартовая строка новой сессии всегда одна и та же:

```
Первым действием выполни: node tools/next-task.mjs
Дальше делай ровно то, что он напечатал. Не составляй план.
```

Статус задачи считается закрытым, если он отмечен в `.planning/BACKLOG.md` **или** все
файлы, которые задача должна была создать, существуют на диске. Поэтому забытая отметка
не приводит к повторному выполнению.

## Документы

- `.planning/CONCEPT.md` — дизайн целиком, источник истины.
- `.planning/ISSUES.md` — 62 задачи, дорожная карта из шести демо-точек D1–D6.
- `.planning/BACKLOG.md` — статусы, ведутся инструментами.
- `.planning/REFERENCE.md` — чек-лист приёмки картинки.

## Инструменты

- `tools/next-task.mjs` — промт следующей задачи.
- `tools/finish-task.mjs` — закрытие задачи, коммит, следующий промт.
- `tools/gh-issues.mjs` — заливка задач в GitHub issues (нужен `GITHUB_TOKEN`).
- `tools/shape-check.mjs` — метрики форм глифового поля (появляется в задаче N27).

## Проверка результата

Отчёту модели не верить. Проверять командами: `git status`, `git log`, `npm test`,
команда проверки из самой задачи, консоль браузера на `http://localhost:5173`.
Отдельно смотреть, не ослаблены ли пороги в тестах и не удалены ли проверки.
